FinanceIA

The finance system of Pablo's Serralheria, a metal structures shop in Brazil. You upload the bank statement, the AI reads and classifies it, and the system matches it against invoices and expenses so everything adds up.

The problem

The shop's finances were done by hand, in spreadsheets, and took hours every month.

  • Every line of the bank statement was copied by hand into a spreadsheet.
  • Someone had to tell by eye what was a sale, what was an expense and what was just money moving between the company's own accounts.
  • Quotes and receipts were made one by one, with no link to what was later billed.

The solution

Upload the statement and let the system do the heavy lifting, with a person reviewing before anything is saved.

  • The AI reads the PDF statement and classifies every transaction. With Excel, amounts are read exactly and the AI only assigns the category.
  • Every bank transaction is matched to its invoice or expense, and the system suggests the pairs.
  • PDF quotes and receipts that become an invoice or an expense in one click.

How it's built

Three separate layers. The screen never talks to the AI: the server sends the document to Claude and is the only one holding the key.

Screens

React + Vite (PWA)

What the user sees. Installs as an app on the phone (PWA).

Server

PHP 8.2, one file per action

Checks session and permissions, applies the business rules, builds the PDFs and talks to the AI.

The 7 screens

Each screen has its own part on the server. The dashboard brings all the numbers together.

DashboardBalance of each account, money still to come in and go out, and the month compared with the previous one.
ExtratosUpload the bank statement, review what the AI read, confirm and reconcile.
FaturamentoFormal and informal invoices, partial payments and what is still to be received.
DespesasExpenses by category, with due dates and payments across several accounts.
OrçamentosQuotes with items and materials, as PDF. Once approved, it becomes an invoice in one click.

The journey of a piece of data

What happens, step by step, when a bank statement is uploaded.

  1. 1

    The file is chosen

    On the Extratos screen the user uploads the bank's PDF or Excel file.

  2. 2

    Entry checks

    Requests from other sites are blocked and only an administrator can upload.

  3. 3

    The file is checked

    10 MB at most, and the real file type is read from its content, not its name.

  4. 4

    Two paths

    Excel: amounts are read exactly, without AI, and the AI only classifies. PDF: Claude reads the document and returns the transactions as JSON.

  5. 5

    House rule

    Any transaction with the company's own tax ID or name is an internal transfer: neither a sale nor an expense.

  6. 6

    No duplicates

    If there is already a statement for that bank and month, it is rejected.

  7. 7

    Human review

    The screen shows everything that was read. Nothing is saved until the person confirms.

  8. 8

    Reconciliation

    Each transaction is matched to its invoice or expense: same amount, same direction, and the fewest days apart wins.

Security

It is the company's money, so every request is checked on the server.

PasswordsStored as bcrypt hashes, never as plain text.
Password resetSingle-use link, stored hashed and with an expiry.
AI keyOnly on the server, outside Git. The browser never sees it.
Login attemptsAt most 5 attempts every 15 minutes per IP.
Forged requests from other sitesBlocked before reaching the logic (CSRF protection).
Uploaded filesSize limit and real file type checked.
PermissionsAdministrator or read-only, checked on every request.
Audit logRecords who did what and when.

Quality and delivery

  • 102 automated tests: 84 on the server (PHPUnit) and 18 on the screens (Vitest).
  • Tests run on their own in GitHub Actions on every push, with a temporary MySQL database.
  • Rules that must never break, written down and tested because each came from a real bug (for example, converting a quote twice does not create two invoices).
  • Closed month: after closing, nobody can change that month's numbers.
  • Database backup before every deploy.
